## Code Review Process

### Review Checklist

**For Algorithm Implementations:**
- [ ] Code follows style guide (PEP 8 for Python, Java conventions)
- [ ] All tests pass
- [ ] Documentation is complete and clear
- [ ] Performance is acceptable
- [ ] Edge cases are handled
- [ ] Error handling is appropriate
- [ ] Code is readable and maintainable

**For Documentation:**
- [ ] All required sections present
- [ ] Examples are clear and correct
- [ ] Grammar and spelling checked
- [ ] Links work correctly
- [ ] Formatting is consistent

### Review Process

1. **Submit**: Create pull request
2. **Automated Checks**: CI/CD runs tests
3. **Peer Review**: 1-2 reviewers check code
4. **Feedback**: Reviewers provide comments
5. **Update**: Author addresses feedback
6. **Approve**: Reviewers approve changes
7. **Merge**: Changes merged to main

### Review Guidelines

**For Reviewers:**
- Be constructive and respectful
- Focus on code, not person
- Explain why, not just what
- Suggest improvements
- Approve when ready

**For Authors:**
- Respond to all comments
- Make requested changes
- Ask questions if unclear
- Thank reviewers
- Learn from feedback

## Pair Programming Exercises

### Setup

**Pairing:**
- Driver: Writes code
- Navigator: Reviews and guides
- Rotate every 15 minutes

**Tools:**
- Screen sharing (Zoom, Teams)
- Code editor (VS Code Live Share)
- Communication (Slack, Discord)

### Exercises

**Exercise 1: Implement Algorithm (30 min)**
- Driver implements algorithm
- Navigator reviews and suggests
- Both test together
- Rotate roles

**Exercise 2: Debug Code (20 min)**
- Start with buggy code
- Navigator finds bugs
- Driver fixes bugs
- Both verify solution

**Exercise 3: Optimize Code (25 min)**
- Start with working code
- Navigator suggests optimizations
- Driver implements improvements
- Both measure performance

## Contribution Guidelines

### How to Contribute

1. **Fork Repository**: Create your fork
2. **Create Branch**: `git checkout -b feature/algorithm-name`
3. **Make Changes**: Implement algorithm
4. **Test**: Run tests, verify correctness
5. **Commit**: `git commit -m "Add algorithm X"`
6. **Push**: `git push origin feature/algorithm-name`
7. **Pull Request**: Create PR with description

### Contribution Types

**Algorithm Implementation:**
- New algorithm
- Improvement to existing
- Bug fix
- Performance optimization

**Documentation:**
- Fix typos
- Improve explanations
- Add examples
- Translate content

**Tools:**
- New scripts
- Improvements to existing
- Bug fixes
- New features

### Code Standards

**Python:**
- PEP 8 style guide
- Type hints for public functions
- Docstrings for all functions
- 4 spaces indentation
- Max 79 characters per line

**Java:**
- Java conventions
- Javadoc comments
- Proper naming
- 4 spaces indentation
- Max 100 characters per line

**Size**: 4-6 students

- Review algorithms learned

- Practice problems

**Coding Sessions:**
- Implement algorithms together
