# Бинарный поиск

## Простое объяснение

Бинарный поиск — это алгоритм поиска определённого элемента в структуре данных.
Алгоритм проверяет элементы по определённой стратегии, пока не найдёт нужный или не убедится,
что его нет.

## Где применяется

- поиск слова в словаре или энциклопедии;
- поиск элемента в отсортированном массиве в программировании;
- поиск записи в телефонной книге (если она отсортирована);
- поиск значения в отсортированных базах данных;

## Пример

Ищем оценку "4" в отсортированном списке: [1, 2, 3, 4, 5, 6, 7]

Шаг 1: Смотрим середину → индекс 3, значение 4 → найдено!

Если бы искали "2":
Шаг 1: Середина → индекс 3, значение 4, ищем слева → [1, 2, 3]
Шаг 2: Середина левой части → индекс 1, значение 2 → найдено!

Если бы искали "6":
Шаг 1: Середина → индекс 3, значение 4, ищем справа → [5, 6, 7]
Шаг 2: Середина правой части → индекс 1, значение 6 → найдено!

Бинарный поиск очень эффективен: за 1-2 шага находит элемент в списке из 7 чисел!

## Вопросы для самопроверки

### Базовые

1. Почему бинарный поиск работает только с отсортированными списками?
2. Сколько шагов нужно для поиска в списке из 1000 элементов?
3. Что происходит, если искомый элемент отсутствует?

### Средние

1. Почему бинарный поиск быстрее линейного?
2. Как найти первое или последнее вхождение элемента?
3. Можно ли использовать бинарный поиск для нечисловых данных?

### Сложные

1. Какова временная сложность бинарного поиска?
2. Как работает бинарный поиск в многомерных массивах?
3. Как оптимизировать бинарный поиск для очень больших данных?

## Практические задания

### Уровень 1 (Лёгкий)

Найди число 7 в отсортированном списке: [1, 3, 5, 7, 9, 11, 13].
Выведи каждый шаг поиска.

### Уровень 2 (Средний)

Найди все вхождения числа 5 в отсортированном списке: [1, 3, 5, 5, 5, 7, 9].
Определи первое и последнее вхождение.

### Уровень 3 (Продвинутый)

Реализуй бинарный поиск с подсчётом сравнений. Сравни время работы
с линейным поиском на списках разного размера (100, 1000, 10000 элементов) и
построй график сравнения.
